How GustBot's AI Pipeline Works

GustBot is a Telegram bot I designed and built solo, from architecture to production. It replaces manual monitoring of dozens of financial sources with a single channel — AI analyzes the market in real time and delivers a structured takeaway in seconds. This post covers how it works under the hood, without the marketing wrapping.

Why build this at all

Traders and investors physically can't keep up with dozens of sources at once — markets move faster than a person can read and cross-reference the news. The goal wasn't "another news bot," but to take the routine off entirely: collection, analysis, output — leaving only what actually moves the price.

Data processing pipeline

At the core is a multi-stage pipeline: market data collection → normalization and deduplication → AI processing → publishing. Each stage is isolated from its neighbors. This matters: if one data source goes down, it shouldn't take down the whole chain — the remaining stages keep working on the data already available.

Prompt engineering — not one prompt for everything

Each topic — crypto, gold, macro, geopolitics — gets its own LLM role with its own style and analytical focus. That was a deliberate choice: a universal prompt across all topics produces a flat, generic result. Separately, I designed a prompt pipeline for the channel's regular content so that topics don't repeat day to day — the model "remembers" what's already been published.

Technical analysis and alerts

For key assets (BTC, ETH, gold, oil, S&P 500, dollar index), the bot computes classic indicators — RSI, EMA, MACD, support/resistance levels — and produces a final signal: bullish, bearish, or neutral. Separately, there are price alerts: the user sets a condition ("tell me when gold breaks this level"), and the bot watches the price and notifies automatically, with no further action needed.

Background task orchestration

Under the hood are a dozen independent recurring jobs — from checking alerts every five minutes to generating content once a day. All of them run on a single scheduler without blocking each other or the bot's main message-handling loop. This mattered more than it seems at first — without job isolation, one heavy task could stall the bot's response to users.

Fault tolerance — the most underrated part

AI-generated text is unpredictable: the model can produce malformed output at the worst possible moment — right before it's published to the channel. So I built an automatic fallback: the system doesn't drop the post entirely, it degrades gracefully and still delivers content to the user. Separately, there's rate-limiting and flood/abuse protection at the incoming-message layer.

Monitoring

The bot notifies me of failures in real time — a data source going down, API errors — so I can react before users ever notice. For an autonomous system running without constant supervision, that's not optional, it's a requirement.

Result

GustBot runs in production 24/7, fully automated — from data collection to channel publishing — replacing manual monitoring of dozens of sources with one channel and a ready-made takeaway. The architecture is built to withstand unpredictable AI output and data-source outages without manual intervention.
